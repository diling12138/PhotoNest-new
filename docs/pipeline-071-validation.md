# PhotoNest 0.7.1 验证记录

日期：2026-11-11。

## 修复与行为

1. 清空回收站不再把 Windows `0x00270008` 一概视为失败；仅在操作未中止、没有真正失败 HRESULT，且当前用户对应 `$R` 文件确已消失时确认完成。实体仍在、核验权限不足或操作取消时保留照片记录。不增加全局清空或按物理路径强删的替代操作。
2. 默认启用扫描与 AI 联动。扫描的 walking 阶段即可唤醒 AI，增量通知合并，新图可优先于旧库排队；主界面、AI 页和托盘的暂停/继续统一。暂停后当前推理完成也不会把状态错误覆盖为运行中。
3. 按明确系统/软件资源目录过滤，不按图片尺寸、内容或随机文件名推测。新增独立 excluded 状态；已有误收录项隐藏，收藏、标签和 OCR 保留，磁盘照片不被删除。设置管理忽略目录，右键可忽略图片所在文件夹；恢复时补扫该范围。

## 回归证据

最终完整回归共 131 项：129 项通过，2 项原生环境检查因权限限制跳过。

回收站新增模拟测试在修复前出现 2 项失败、1 项错误：实际文件已消失仍误报、回调成功却未核验实体、核验访问被拒未保留记录。修复后这些测试全部通过，另覆盖取消、真正失败、Shell 列表缓存滞后和非回收站路径禁止删除。

对用户已保存数据库仅做只读汇总，8 条残留记录对应的回收文件均已不存在，和截图的 8 项误报吻合。只读核对不读取照片内容，不输出文件名，不修改真实照片或回收站；检查点数据库可能不包含尚未合并的 WAL 状态。

自动化使用临时图库验证边扫描边识别、后台模式增量唤醒、批量通知合并、新图优先、不重复识别、统一暂停、已排队资源被忽略后不再识别，以及忽略/恢复保留人工状态。

完整回归与打包自检结果见构建目录 `all071-tests-final.log`、`build-pipeline071.log` 和 `release071-verification.json`。真实 Windows USN 和真实回收站集成测试若因执行环境权限跳过，不视为原生端到端通过；不会为通过测试而操作真实用户文件。

规则仅覆盖可明确识别的目录结构；自定义安装目录、未识别软件缓存可能仍需使用“忽略所在文件夹”。
