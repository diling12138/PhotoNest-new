# 离线识图使用与维护

## 使用

1. 完整解压便携包，保持 `PhotoNest.exe`、`_internal`、`models` 在同一目录。
2. 首次打开会自动扫描本机固定磁盘，无需添加文件夹；照片会陆续显示，支持暂停/继续。范围可在「设置 → 扫描范围」中管理。
3. 左下角点击「AI 识图」→「开始 / 继续识别」。已有照片会补全索引，新增或修改的照片会在以后扫描完成后自动识别。可以暂停，关闭软件后也会保留已完成的结果。
4. 搜索框可选择「综合搜索」「文字匹配」「画面内容」。综合搜索结合文件名、路径、识别文字、标签和图像语义；画面内容按相关性展示最多 200 张候选，综合搜索最多 500 张。
5. 双击照片，在右侧点击「提取文字」或「识别文字」标签。照片与文字并排显示，支持编辑、复制、导出 TXT、保存纠正；中间分隔条可调整宽度。「框选文字」允许在图片上拖动选区单独识别，框选结果不覆盖整张照片的索引。切换照片时保留当前会话的未保存文字草稿；需要永久保留时点击「保存纠正」。
6. 分类标签显示在查看器和侧栏。点击「编辑标签」手动修正；移除的自动标签不会在重跑时加回。
7. 在「设置 → 外观」选择跟随系统（默认）、浅色或深色；照片查看器与文字区一起切换，主题切换不清空正在编辑的文字。

所有推理在本机 CPU 执行，不要求显卡、Python、登录或联网。首次索引逐张处理，比后续搜索耗时。首次打开识别或进行语义搜索时需加载模型。后台识别与界面分线程，界面可继续浏览；当前照片推理结束后处理暂停或交互请求。

分类是候选标签，不是确定结论；小字、模糊、复杂背景及旋转文字可能识别不全。本版不包含整页方向矫正、表格重建、PDF 排版还原、人脸识别或人物身份判断。图片转文字导出为 TXT。

识别文字、人工纠正、标签、图像向量保存在现有 `library.db`。删除数据库会丢失这些结果，需重新建立。移动到回收站的图片不会进入正常搜索；恢复后重新可用。

诊断命令：`PhotoNest.exe --check-ai --data D:\可写诊断目录`。正常退出后目录中产生 `ai-check.json`，同时检查中英文 OCR、框选识别、图文编码及模型校验。

## 从三份原始模型重新准备

这一步仅供开发者，便携包用户不用做。

1. 三个原文件放在项目根目录。使用 Python 3.12 的独立转换环境。
2. 安装 `cn-clip==1.6.0`、兼容的 PyTorch / torchvision、`paddle2onnx==2.1.0`、`onnx`、`onnxruntime==1.23.2`、`PyYAML` 及其依赖。
3. Windows 上 Paddle2ONNX 的二进制构建依赖固定的 `paddlepaddle==3.0.0.dev20250426`，需要从 [Paddle 官方 nightly 索引](https://www.paddlepaddle.org.cn/packages/nightly/cpu/paddlepaddle/) 安装匹配的 wheel。较新的 Paddle 稳定版不保证 ABI 兼容。
4. 运行 `python tools/prepare_ai_models.py`，导出 OCR ONNX、图像与文字双编码器、字典及词表。脚本尝试图像静态 INT8 和文字动态 INT8，并与官方实现对照。本次 INT8 未通过门限，实际采用 FP16 权重存储、加载时转回 FP32 运算，语义权重体积约减半。选择与验证分数记录在报告中，不能将向量相似度当成检索准确率。
5. 检查 `docs/ai-model-validation.json`，再运行 `python test_ai.py`、`python test_ai.py --models` 和 `python test_ui.py`。
6. `build_exe.bat` 构建便携包，只收录清单引用的部署模型，不包含原始 PT/TAR、转换环境或个人照片库。切换前会先用候选 EXE 进行真实模型自检，旧 EXE、运行库和 ZIP 保存在 `_build/before-ai-release-*`。

转换脚本中 ONNX 内存形状推导用于兼容含中文的 Windows 路径。Paddle 导入时缓存被限制在构建目录。以上开发框架均不随最终应用分发。

模型来源和上游许可证见 `models/NOTICE.md`、`models/licenses`。早期候选方案见 `ai-model-research.md`，其中“尚未实施”的陈述仅描述该文档当时的状态。
